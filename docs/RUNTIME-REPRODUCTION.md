# Runtime source and artifact reproduction

The runtime declarations come from the frozen source snapshot. The distributed runtime directory contains verified-fetch metadata, overlay payloads and the first-party AbstractReal/AbstractRealRat files. Setup materializes the remaining sources/configuration and checks every raw hash in UPSTREAM.json. First-party license headers and the documented comment normalization do not change declarations. The public copy removes one internal coordination label from an opening module doc comment; the original and public source hashes are recorded separately. The public package uses uniform standard Lake options with no build-monitor plugin. Acceptance requires a fresh complete build and a raw-body axiom gate. A successful runtime source replay does not by itself establish that gate.

The historical runtime artifacts came from more than one incremental compilation profile. Some retained artifacts used synchronous elaboration, while others used the default setting. A build-monitor plugin was also active during a later runtime audit. These details can affect generated private matcher names and macro binder hygiene indices without changing source bytes.

A controlled reconstruction used the original source paths, working directory, per-module Lake setup and imported artifacts. Repeated compilations with identical options were byte-stable. Restoring the original source path recovered the historical `SailTests.Widths` artifact. Three remaining artifacts (`Sail.Common`, `Sail.Sail`, and `SailTests.SetSliceInt`) reproduced their historical SHA256 exactly when the historical monitor plugin was restored; the paired compilations without the plugin did not match.

Structured declaration diagnostics localized the synchronous-build differences in those three modules to generated binder names: one unexpander declaration in `Sail.Common`, four unexpander declarations in `Sail.Sail`, and one private matcher in the slice tests. These diagnostics describe the retained artifacts; they are not a new proof of runtime equivalence. The public recipe does not add per-module flags or the historical monitor plugin to imitate an incremental build history.

The model and runtime acceptance conditions are distinct: all 1,481 `ArmFull` artifacts must reproduce the frozen model bytes, and the runtime must pass its complete fresh raw-body gate with its documented uniform recipe. Historical runtime byte differences remain documented rather than represented as exact reproduction by the public recipe. The source/configuration-equivalent fallback passed all four fresh gates and every canonical model hash; see [source-fetch-cold.json](../evidence/source-fetch-cold.json). Final helper wiring was tested separately after the full measurement. Source-export/patch review and publication approval remain separate, and all compiled caches stay private pending runtime permission.
